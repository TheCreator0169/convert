# Decisions

One entry per decision: date, what, why.

- **2026-11-18: no website, no server, no analytics.** The macOS repo's `site/` folder is not reproduced. Why: the user wants a purely local app.
- **2026-11-18: Windows stack = Python 3.13 + PySide6, ffmpeg external, Inno Setup installer.** Why: Python 3.13 is installed (3.14 is too new for native packages), PyInstaller builds an exe, the user accepted the recommendation. ffmpeg is not bundled (licence, size); decision on bundling stays open.
- **2026-11-18: Explorer entry is a registry verb under HKCU.** Why: no admin needed, clean uninstall. Limit: Windows 11 shows it under "Show more options"; top-level needs a sparse MSIX with `IExplorerCommand` (separate mission, not started).
- **2026-11-18: Omega structure reproduced from TURMO's `.claude\` and `docs\` (read only, nothing copied verbatim, nothing else in that repo read).** Same 8 Haiku agents (roles adapted), `omega-delegate`, `reflect`, `release`, build/test/GUI skills renamed `convert-*`, same settings and escalation ladder. The Tk and theme skills became `convert-qt-gui` and `convert-formats`; the LCD and CPU-helper specifics were dropped. Why: the user asked for the same structure for this project.
- **2026-11-18: single instance uses an atomic named mutex, then a local pipe.** The first version (try to connect, else listen) let simultaneous Explorer launches all become windows (seen with three launches of the installed exe). Why mutex: connect-then-listen is a race. The first instance listens before it builds its window; the others retry for 10 s.
- **2026-11-18: the uninstaller removes `%LOCALAPPDATA%\Convert` (logs) without asking and asks before removing `%APPDATA%\Convert` (settings, default keep).** Why: logs are not user data; the first uninstall left a log file.
- **2026-11-18: Memory lives in `docs\`.** `progress.md`, `decisions.md`, `known-issues.md`. No second memory system.
- **2026-11-18: Git was local-only, now has one remote.** The user opened `https://github.com/TheCreator0169/convert` (public, open source, MIT). Rule changed in `CLAUDE.md`: push only on the user's word to that remote. Why: the user wants v0.1.0 public. Before the first push the 6 local commits were rewritten from the user's personal email to the GitHub noreply address (nothing had been pushed); history is now `TheCreator0169 <TheCreator0169@users.noreply.github.com>`.

- **2026-11-19: a daily update notice (D2 answered yes), the one network call.** Once per 24 h while the app is open: one anonymous GET to the GitHub releases API, generic User-Agent, 5 s timeout, on a daemon thread; a newer release shows a plain blue line above the drop box that opens the release page (checked to be a page of this repo). Nothing is downloaded or installed. Off with update_check: false in settings.json. Why: the user asked for it ('only a link, one try a day, if they do not use it we do not care'). CLAUDE.md and the README no longer say 'no network call'. Plan: docs\update-check-plan.md.

- **2026-11-19: the copyright holder stays `TheCreator0169` (the GitHub name).** The user decided it. `LICENSE` and the installer already say so; nothing to change.
- **2026-11-19 and 2026-11-20: light theme and a Theme choice (v0.2.1): System, Dark or Light.** Why: ROADMAP D5 (the light theme follows Windows). The choice is in the right-click menu on the version label at the bottom of the window.
- **2026-11-20: legacy `.doc` is read by our own olefile reader, text only (v0.2.2).** Why: no LibreOffice; the sharepoint-to-text package was rejected because it needs about 10 dependencies. Pictures, formatting, headers, footnotes and text boxes are not read.
- **2026-11-20: UNC paths are refused (v0.1.15); v0.2.3 also refuses device paths, `\\?\` forms and mapped network drives.** Why: the advice in ROADMAP-next D8 (refuse `\\server\share` files), answered by the code.
- **2026-11-20: the user stopped at v0.2.2 and asked for a cleanup release, v0.2.3. The Windows 11 top-level menu is deferred and would be v0.2.4.** Why: the signing route (SignPath Foundation, a paid certificate of about 220-300 USD a year, or none) and the C++ toolchain (VS Build Tools, Windows SDK) are not decided; ROADMAP D4 is involved.
- **2026-11-21: Windows 11 menu through a sparse MSIX package and a native C++ IExplorerCommand DLL (v0.2.4, in progress).** Why: the user wanted the entry at the top level of the Windows 11 menu. The package is `TheCreator0169.Convert`; the DLL hides the entry unless a supported file is selected. Limit: on the user's build 26300 Windows lists it under "Applications extensions" in the short menu, not at the root. The "Show more options" HKCU verb stays.
- **2026-11-21: no SignPath and no paid certificate for the MSIX.** Why: the user decided no SignPath (SmartScreen is a separate matter). Registering a sparse MSIX needs a trusted signature, and a self-signed certificate trusted on the machine is enough for that. The certificate is CN=TheCreator0169, created by `tools\make_msix.ps1`; its private key is deleted at the end of the build. ROADMAP D4 stays "no code signing for the installer".
- **2026-11-21: the certificate is trusted in LocalMachine\TrustedPeople, with one UAC prompt, not per user.** Why: Cert:\CurrentUser\TrustedPeople does not work: Add-AppxPackage fails with 0x800B0109, although Microsoft Learn suggests it. The installer stays PrivilegesRequired=lowest; only the optional task `win11menu` (Windows 11 only, ticked by default) asks for elevation, in its own step (`register.ps1 -TrustOnly`). Uninstall asks again only when `HKCU\Software\Convert\Win11Trust` exists, to remove the certificate (`unregister.ps1 -CertOnly`). Why this replaces the earlier plan (paid signing): see the entry above.
- **2026-11-21: installer debugging rules (kept for later edits to `convert.iss`).** `ShellExecute` with the `runas` verb cannot see the Sysnative folder (error code 3), so elevated entries use `{sys}`. An Inno `[Run]` entry with `shellexec` needs `waituntilterminated`, or the installer does not wait. `skipifdoesntexist` silently skipped the `{sysnative}` entries, so the Windows 11 steps use Check functions instead.

- **2026-11-25: quick-convert flyout in the Windows 11 menu (v0.2.5, in progress).** The 'Convert' entry opens a flyout of 'Convert to <format>' items for the file type's quick targets (`formats.QUICK`), then 'Open Convert...'. A quick item runs `Convert.exe --quick <fmt> files...`: no window, output beside the original, a Windows toast notification (PowerShell, sender key HKCUSoftwareClassesAppUserModelIdConvert.QuickConvert, removed by uninstall; the Qt tray balloon never appeared on build 26300). Why: the user's request of 2026-11-21 (a WinRAR-like submenu). The classic 'Show more options' entry gets no flyout in this version; the shell extension reads its items from the selection remembered in GetState, with the 'Open Convert...' fallback when that is not available. `shell_ext\quick.h` and `exts.h` are generated from `formats.QUICK` and `EXT_TYPE` by `tools\gen_ext_header.py`, so the lists cannot drift apart unnoticed.
